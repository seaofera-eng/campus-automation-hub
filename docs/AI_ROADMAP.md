# AI 기능 로드맵 (2·3단계)

## 지금 상태

1단계에서는 **AI 기능을 하나도 구현하지 않았습니다.** 인터페이스와 빈 어댑터,
예약 테이블만 있습니다.

```
src/adapters/ai/
  types.ts    6개 서비스 인터페이스 + 임계값·가중치 상수
  noop.ts     전부 { enabled: false, phase, message } 만 반환
  index.ts    getAiServices() · getAiFeatureFlags() — 전부 false
```

### 가짜 결과를 만들지 않는 구조

요구사항 2번은 "가짜 AI 분석 결과를 실제 결과처럼 표시하지 않는다"입니다.
이것을 **문서 약속이 아니라 코드 구조로** 지켰습니다.

- Noop 어댑터에는 점수·유사도 숫자를 만드는 코드 경로가 **아예 없습니다.**
  반환 타입이 `AiFeatureDisabled` 라 숫자를 넣을 자리가 없습니다.
- 화면은 `<PhaseNotice>` 컴포넌트만 렌더합니다. 자리표시용 막대그래프나 흐린
  숫자를 함께 그리지 않습니다 — "가려진 실제 결과"처럼 보이면 안 되기 때문입니다.
- 검토 화면의 "참고용 제안 등급"은 AI 가 아니라 **체크된 항목 수를 세는 단순
  규칙**이며, 화면에도 그렇게 적혀 있습니다.

## 2단계

### 중복 탐지 (DuplicateDetectionService)

등록 신청된 도구를 기존 도구와 비교해 중복 가능성을 알립니다.

비교 기준 11개 필드는 `DUPLICATE_COMPARISON_FIELDS` 에 상수로 있습니다:
이름, 한 줄 소개, 설명, 해결하려는 문제, 주요 기능, 입력 자료, 결과물,
현재 업무 흐름, 자동화 후 흐름, 연동 시스템, 카테고리.

임계값(`DEFAULT_DUPLICATE_THRESHOLDS`):

| 구간 | 점수 | 화면 처리 |
|---|---|---|
| 거의 동일 | 85 이상 | 등록 전 확인 요청 |
| 상당 부분 겹침 | 70 이상 | 검토자에게 경고 |
| 관련 있음 | 50 이상 | 참고 정보로 표시 |

**자동으로 등록을 막지 않습니다.** 사람이 보고 판단하도록 정보만 줍니다.

붙일 곳: `src/application/tools/register.ts` 의 `submitTool()` 직후.
결과는 `duplicate_detection_runs` / `duplicate_candidates` 테이블에 저장.

### 위험 자동 평가 (RiskAssessmentService)

지금의 14항목 체크리스트를 입력으로 받아 **초안**을 제안합니다.
`tool_data_classifications` 행 구조가 이미 이 입력에 맞게 설계되어 있습니다.

**최종 확정은 계속 사람이 합니다.** 자동 등급으로 상태를 바꾸지 않습니다.
`risk_assessments` 테이블에 제안값을 남기고, 검토자가 수용/수정한 결과가
`risk_checklists` 에 저장됩니다.

### 수요-도구 자동 매칭 (DemandMatchingService)

수요 내용과 도구 설명을 비교해 후보를 제안합니다.
지금의 수동 매칭 UI 는 그대로 두고, 후보 목록만 미리 정렬해 주는 형태가 됩니다.
연결 유형과 사유는 계속 사람이 정합니다.

## 3단계

### 멀티 LLM 검증 (MultiLlmReviewService)

여러 모델에 같은 도구 설명을 주고 평가를 받아 의견이 갈리는 지점을 표시합니다.
`llm_review_runs` / `llm_review_results` 에 모델별 응답을 그대로 저장해
나중에 검증할 수 있게 합니다.

### 순위 (RankingService)

가중치(`DEFAULT_RANKING_WEIGHTS`, 요구사항 16번):

| 항목 | 가중치 |
|---|---|
| 사용자 평가 | 30% |
| 실사용량 | 20% |
| 업무 시간 절감 | 15% |
| 확산도(타 부서 사용) | 10% |
| 안정성 | 15% |
| 비용 효율 | 5% |
| 개선 대응 | 5% |

보정 규칙(`DEFAULT_RANKING_GUARDS`):

- 평가 5건 미만은 순위에 넣지 않습니다.
- 베이지안 보정(사전 가중치 5)으로 평가 수가 적은 신규 도구가 과대평가되는 것을
  막습니다. 함수는 이미 `src/domain/evaluation/scoring.ts` 에 있고 **아직 아무도
  호출하지 않습니다.**
- `SUSPENDED`·`RETIRED` 도구는 순위에서 제외합니다.

### 기여 토큰 (RewardService)

`reward_ledgers` 는 해시 체인 컬럼을 갖습니다. 지급 기록이 나중에 조작되지
않았음을 확인할 수 있어야 하기 때문입니다.

## 붙일 때 지켜야 할 것

1. **`getAiServices()` 의 반환 타입을 바꾸지 마세요.** Noop 과 실제 구현이 같은
   인터페이스를 만족해야 기능 플래그로 껐다 켰다 할 수 있습니다.
2. **AI 결과로 상태를 자동 전환하지 마세요.** 상태머신은 사람의 판단을 전제로
   설계되어 있습니다. AI 는 제안까지입니다.
3. **결과가 없을 때 0 이나 빈 값을 표시하지 마세요.** "아직 분석하지 않음"과
   "분석했는데 0점"은 다릅니다.
4. **원본 응답을 저장하세요.** 모델이 바뀌면 과거 판단을 재현할 수 없습니다.

# Vercel 에 시연용으로 올리기

심사위원이 아무 때나 들어와 눌러 볼 수 있도록 공개 주소를 만드는 방법입니다.

> 결론부터 — **됩니다.** 코드는 그대로 두고 환경변수 세 개만 넣으면 됩니다.
> 다만 **저장이 오래 유지되지 않는다는 제약**이 하나 있습니다. 3절에 적었습니다.

---

## 1. 준비

### 왜 그냥 되는가

- 이 앱은 데이터를 **파일 하나**(`demo-db.json`)에 담습니다. 데이터베이스가 필요 없습니다.
- 그 파일이 없으면 **코드에 들어 있는 시드 데이터로 스스로 만듭니다.**
  미리 돌려 둔 AI 분석 결과(중복 판정 10건·위험도 10건·품질검증 10건·수요매칭 7건)가
  시드에 함께 들어 있어서, 새 서버에서도 **분석 결과가 그대로 보입니다.**
- 화면에서 AI 를 부르는 곳은 「수요 신청서 초안 다듬기」 하나뿐이고,
  **키가 없으면 규칙으로 만든 초안으로 넘어갑니다.** 멈추지 않습니다.
- 검색 노출은 이미 막아 두었습니다 (`robots: index false`).

### 로컬에서 미리 확인했습니다

Vercel 과 같은 조건(빈 데이터 폴더 + AI 키 없음)으로 돌려 봤습니다.

```
DEMO_DATA_DIR=<빈 폴더> AI_GATEWAY_API_KEY= pnpm start
```

- 시드가 자동 생성됨 — 도구 7건, 중복분석 10건
- 「미팅 노트 자동 정리기」 중복 판정 **92점** 그대로 나옴
- 로그인·마법사·추천 결과 정상
- 수요 초안: AI 없이 **"고르신 내용을 그대로 옮겨 적었습니다"** 로 안내하고 진행됨

## 2. 배포 순서

### 2-1. GitHub 에 올리기

지금 저장소에 원격이 없습니다. 먼저 GitHub 저장소를 만들고 연결합니다.

```powershell
git remote add origin https://github.com/<계정>/<저장소>.git
git push -u origin main
```

> **`.env.local` 은 올라가지 않습니다.** `.gitignore` 에 들어 있고,
> 지금까지 커밋에 한 번도 포함된 적이 없는 것을 확인했습니다.
>
> **저장소는 비공개(Private)로 두세요.** Vercel 은 비공개 저장소도 배포할 수 있습니다.

### 2-2. Vercel 에서 가져오기

1. vercel.com 로그인 → **Add New → Project**
2. 방금 만든 저장소 선택 → **Import**
3. 설정은 손대지 않아도 됩니다. Next.js 를 자동으로 알아봅니다.
   (빌드 명령 `next build`, 패키지 매니저 pnpm 자동 인식)

### 2-3. 환경변수 세 개

**Deploy 를 누르기 전에** Environment Variables 에 넣습니다.

| 이름 | 값 | 왜 필요한가 |
|---|---|---|
| `DEMO_DATA_DIR` | `/tmp/campus-demo` | Vercel 은 프로젝트 폴더에 쓸 수 없습니다. 쓸 수 있는 곳은 `/tmp` 뿐입니다 |
| `DEMO_SESSION_SECRET` | 임의의 32자 이상 문자열 | 로그인 쿠키 서명용. 데모 전용이며 실제 인증에 쓰지 않습니다 |
| `NEXT_PUBLIC_APP_URL` | `https://<프로젝트>.vercel.app` | 절대 주소가 필요한 곳에 씁니다 |

`NEXT_PUBLIC_DEMO_MODE` 는 넣지 않아도 됩니다. 기본값이 데모 모드입니다.

임의 문자열은 이렇게 만들면 됩니다.

```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

### 2-4. 지역 설정 (권장)

배포 후 **Project Settings → Functions → Region** 을 **Seoul (icn1)** 로 바꾸세요.

- 심사위원이 국내에서 접속하므로 응답이 빨라집니다.
- 지역이 하나로 고정되면 서버 인스턴스가 덜 흩어져서, 3절의 제약이 완화됩니다.

### 2-5. 확인

배포가 끝나면 주소로 들어가 이 순서로 눌러 보세요.

1. 첫 화면이 뜨는가
2. 로그인 → **이검토** 선택
3. 검토 작업 → **[예시] 미팅 노트 자동 정리기** (미검토)
4. 검토 시작 → 2단계에서 **「사실상 같은 도구 92점」** 이 나오는가

4번까지 나오면 시연 준비가 끝난 것입니다.

## 3. 알아 두셔야 할 제약

### 저장한 내용이 오래 유지되지 않습니다

Vercel 은 요청이 올 때마다 서버를 띄웁니다. 그 서버의 `/tmp` 는
**그 서버에만 있는 공간**입니다. 그래서

- 서버가 새로 뜨면 → **시드 데이터로 처음부터** 다시 시작합니다.
- 여러 심사위원이 동시에 들어오면 → 서로 **다른 서버**에 붙을 수 있고,
  그러면 한 사람이 올린 도구가 다른 사람에게 안 보일 수 있습니다.

**얼마나 문제인가**

- **둘러보기·검색·마법사·추천**은 전혀 영향이 없습니다. 읽기만 하기 때문입니다.
- **검토 5단계**도 대부분 괜찮습니다. 시드에 이미
  「미팅 노트 자동 정리기」가 미검토 상태로 들어 있어서, 심사위원이 검토 시작부터
  승인까지 한 번에 돌려 볼 수 있습니다.
- **한 사람이 올린 것을 다른 사람이 확인하는 시연**은 보장되지 않습니다.

**중요한 점** — 데이터가 날아가도 **화면이 깨지지 않습니다.**
언제나 완전한 시드 데이터로 다시 시작하므로, 심사위원은 항상
제대로 된 데모를 봅니다. 이상하면 새로고침하면 됩니다.

### 안내 문구를 붙이는 것을 권합니다

첫 화면이나 제출 자료에 한 줄 적어 두면 오해가 없습니다.

> 이 주소는 심사용 체험판입니다. 모든 자료는 가상의 예시이며,
> 올리신 내용은 일정 시간 뒤 초기화됩니다.

### 누구나 관리자 계정으로 들어올 수 있습니다

데모 로그인은 비밀번호가 없습니다. 주소를 아는 사람은 관리자 화면까지 볼 수 있습니다.

- 심사 목적에는 **의도된 동작**입니다. 역할별로 화면이 어떻게 다른지 보여 줘야 하니까요.
- 검색 노출은 이미 막아 두었습니다. **주소를 공개된 곳에 올리지 마세요.**
- 실제 개인정보는 한 건도 들어 있지 않습니다.

### AI 키는 올리지 않아도 됩니다

교내 AI 게이트웨이 키(`AI_GATEWAY_API_KEY`)를 Vercel 에 넣지 **않는 것을 권합니다.**

- 넣지 않아도 **화면에 보이는 AI 분석 결과는 전부 그대로 나옵니다.**
  미리 돌려 둔 결과가 시드에 들어 있기 때문입니다.
- 영향받는 것은 「수요 신청서 초안 다듬기」 하나뿐이고, 규칙 초안으로 대체됩니다.
- 넣지 않으면 **키가 외부 호스팅 업체에 저장되지 않습니다.**
- 교내 게이트웨이가 학내망에서만 열려 있다면 넣어도 호출이 실패할 수 있습니다.
  (확인해 보지 않았습니다.)

초안 다듬기까지 보여 주고 싶으시면 넣으시되, **대회가 끝난 뒤 키를 새로
발급받으세요.**

## 4. 저장이 유지되게 하려면 (선택)

3절의 제약을 없애려면 데이터를 **서버 밖 한 곳**에 두면 됩니다.

지금 구조에서는 파일을 읽고 쓰는 함수가 **두 개뿐**입니다
(`readFromDisk`, `writeToDisk`). 이 둘만 외부 저장소용으로 바꾸면 되고,
나머지 코드는 손대지 않아도 됩니다.

| 방법 | 드는 시간 | 비고 |
|---|---|---|
| **Vercel Blob** | 반나절 | Vercel 안에서 바로 붙습니다. 무료 한도로 충분합니다 |
| **Upstash Redis** | 반나절 | 동시 쓰기에 더 안전합니다 |
| **Supabase 연결** | 하루~ | 제대로 된 방법. 설계도 18개와 구현이 이미 있지만 **실제로 붙여 본 적이 없어** 대회 직전에는 위험합니다 |

**대회 전에는 3절 제약을 안고 가는 것을 권합니다.** 심사위원이 보는
핵심 흐름(둘러보기 → 마법사 → 검토 5단계 → 승인)은 지금 상태로 전부 돌아갑니다.

## 5. 자주 겪는 문제

**빌드는 됐는데 화면이 500 을 냅니다**
`DEMO_SESSION_SECRET` 을 넣었는지 확인하세요. 16자 미만이면 시작할 때 막힙니다.

**로그인이 안 됩니다**
`DEMO_DATA_DIR` 이 `/tmp` 로 시작하는지 확인하세요. 다른 경로면 쓰기가 막힙니다.

**분석 결과가 "아직 돌리지 않았습니다"로 나옵니다**
시드에 없는 도구입니다. 심사용으로는 `[예시]` 가 붙은 도구를 보시면 됩니다.

**올린 도구가 사라졌습니다**
3절의 제약입니다. 고장이 아닙니다.

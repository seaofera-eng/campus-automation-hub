# 업무 흐름

## 역할

| 역할 | 하는 일 |
|---|---|
| **수요자** (REQUESTER) | 업무 수요 등록, 도구 검색·평가, 개선 요청 |
| **개발자** (DEVELOPER) | 도구·버전 등록, 개발 수요 참여, 배정된 개선 요청 처리 |
| **검토자** (REVIEWER) | 도구 검토, 위험 체크리스트 작성, 시범운영 승인, 수요-도구 연결 |
| **관리자** (ADMIN) | 모든 조회, 역할 관리, 정식 승인·사용중지·폐기 |

## 도구 상태 전환

```
                    ┌──────────────────────────────┐
                    ↓                              │
  임시저장 ──→ 등록 신청 ──→ 담당자 검토 ──→ 보완 요청 ─┘
   DRAFT      SUBMITTED     HUMAN_REVIEW    REVISION_REQUIRED
                                 │
                                 ↓
                            시범운영 ──→ 정식 승인 ⇄ 사용 중지
                             PILOT       APPROVED    SUSPENDED
                                             │           │
                                             └─→ 폐기 ←──┘
                                                RETIRED
```

전환 10종과 각각의 역할 제약은 `src/domain/tool/status-machine.ts` 에 있습니다.

| 전환 | 누가 | 조건 |
|---|---|---|
| 임시저장 → 등록 신청 | 개발자(담당자 본인), 관리자 | — |
| 등록 신청 → 담당자 검토 | 검토자, 관리자 | — |
| 담당자 검토 → 보완 요청 | 검토자, 관리자 | — |
| 보완 요청 → 등록 신청 | 개발자(담당자 본인), 관리자 | — |
| 담당자 검토 → 시범운영 | 검토자, 관리자 | **체크리스트 필요 + CRITICAL 아님** |
| 시범운영 → 정식 승인 | **관리자만** | **체크리스트 필요 + CRITICAL 아님** |
| 정식 승인 → 사용 중지 | **관리자만** | — |
| 사용 중지 → 정식 승인 | **관리자만** | — |
| 정식 승인/사용 중지 → 폐기 | **관리자만** | — |

모든 상태 변경에는 **5자 이상의 이유**가 필요하고, `tool_status_history` 에
영구히 남습니다.

### 위험도 차단 (요구사항 15번)

위험 체크리스트가 없거나 등급이 `CRITICAL` 이면 **시범운영·정식 승인으로 갈 수
없습니다.** 화면에서 버튼이 아예 나오지 않고, 요청을 직접 보내도 서버가 막습니다.

체크리스트 14항목은 검토자가 **직접 판단해서** 표시합니다. 화면에 "참고용 제안
등급"이 보이지만 이는 체크된 항목 수를 세는 단순 규칙이며, 화면에도 "AI 분석
결과가 아니다"라고 적혀 있습니다. 저장되는 값은 검토자가 고른 등급입니다.

해당된다고 표시한 항목에는 **적용한 통제 방안 입력이 필수**입니다. 체크만 하고
넘어가면 나중에 무엇을 확인했는지 알 수 없습니다.

## 수요 상태 전환

```
임시저장 ──→ 공개 ──┬──→ 도구 연결됨 ──┬──→ 개발 중 ──→ 시범운영 ──→ 완료
 DRAFT      OPEN    │     MATCHED     │  IN_DEVELOPMENT   PILOT     COMPLETED
                    │                 └──→ 완료
                    └──→ 개발 중
                    (모든 상태에서 종료 CLOSED 가능)
```

도구와 달리 **검토를 거치지 않습니다.** 수요는 "이런 게 필요합니다"라는 요청이지
승인 대상이 아니기 때문입니다. 등록자가 직접 공개하고 종료합니다.
다만 개발 단계 전환(개발 시작, 시범운영)은 검토자·관리자 몫입니다.

### 수요-도구 연결

**자동 추천이 아닙니다.** 검토자·관리자가 목록에서 도구를 직접 고르고,
연결 유형 5종 중 하나를 선택하고, 왜 그렇게 판단했는지 10자 이상 적습니다.

| 연결 유형 | 뜻 |
|---|---|
| 바로 사용 가능 | 지금 그대로 쓸 수 있다 |
| 설정 변경 후 사용 가능 | 설정만 바꾸면 된다 |
| 기존 도구 개선 필요 | 기능을 더해야 한다 |
| 여러 도구 조합 필요 | 하나로는 안 되고 조합해야 한다 |
| 신규 개발 필요 | 맞는 도구가 없다 |

유사도 점수 같은 값은 계산하지도 보여주지도 않습니다. 자동 매칭은 2단계 몫입니다.

## 개선 요청 상태 전환

```
접수 ──→ 검토 중 ──┬──→ 반영 확정 ──→ 처리 중 ──→ 반영 완료 ──→ 종료
OPEN    REVIEWING  │    ACCEPTED    IN_PROGRESS   RELEASED     CLOSED
  │                └──→ 반려 ──→ 종료
  └──→ 종료 (요청자 철회)      REJECTED
```

- 요청자는 자기 요청을 **철회**(접수 → 종료)하거나 완료 후 **종료**할 수 있습니다.
- 배정된 담당 개발자는 처리 단계를 진행할 수 있습니다.
- 배정되지 않은 개발자는 상태를 바꿀 수 없습니다.

## 평가

- **시범운영·정식 승인 상태의 도구만** 평가할 수 있습니다. 아직 써 볼 수 없는
  도구를 평가하는 것은 의미가 없습니다.
- 7개 항목을 각각 1~5점으로 매깁니다.
- **평가는 버전에 붙습니다.** 새 버전이 나오면 다시 평가할 수 있습니다.
- **같은 사용자가 같은 버전을 중복 평가할 수 없습니다.**
- 수정하면 이전 값이 `evaluation_history` 에 남습니다. 이력은 지울 수 없습니다.

평가가 없는 도구는 **0점이 아니라 "평가 없음"**으로 표시합니다.
0점은 "나쁜 평가를 받았다"로 읽히기 때문입니다.

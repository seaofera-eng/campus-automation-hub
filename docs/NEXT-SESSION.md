| | 리뷰용 | 디자인 작업용 |

```powershell

# 디자인 확인용 (worktree) — 다른 터미널에서
```

## 3. 내일 할 일 (순서대로)

### ① 전체 흐름 리뷰 — [REVIEW-2026-08-26.md](REVIEW-2026-08-26.md)

실제로 만드신 자동화 도구를 올려서 수요 등록 → 개발 → 검토 → 승인 → **평가**까지
한 바퀴 도는 양식입니다. 화면 순서가 아니라 일하는 순서로 짜여 있습니다.

**한 절씩 끝날 때마다 알려 주시면 바로 반영합니다.** 전체를 다 기다리지 않는 편이
시간을 제일 많이 아낍니다.

> ⚠️ **새 도구를 올리면 그 도구의 AI 분석이 비어 있습니다.**
> "아직 돌리지 않았습니다"가 뜨는데 고장이 아닙니다. 분석은 미리 돌려 두는
> 구조라서 그렇습니다. 채우려면:
>
> ```powershell
> pnpm ai:analyze -- --only=duplicates   # 중복만, 빠름
> pnpm ai:analyze                        # 전부 (32회, 약 $1.2)
> pnpm demo:reset                        # 결과를 데모 데이터에 반영
> ```
>
> 이 설계가 맞는지도 양식 8.3 에서 묻고 있습니다.

## 5. 조심할 것

- **API 키가 대화 기록에 평문으로 남았습니다.** 작업이 끝나면 포털에서 한 번
  갈아 주세요. 키는 `.env.local`(gitignore)에만 있고 커밋에는 안 들어갔습니다.
  워크트리에도 같은 파일을 복사해 두었습니다.
- **모델을 내리지 않기로 했습니다.** 필요하면 `.env.local` 에서
  `AI_JUDGE_MODEL` 로 바꿀 수 있고, 실행이 끝나면 기능별 비용이 표로 찍힙니다.
  다만 품질검증의 두 관점이 같은 모델로 겹치면 교차 검증이 아니라서 경고가 뜹니다.
- **`seed-analyses.ts` 를 손으로 고치지 마세요.** `pnpm ai:analyze` 가 통째로
  덮어씁니다.
- 되돌리기 전에 읽어야 할 결정은 [DECISIONS.md](DECISIONS.md) 와
  루트 `CLAUDE.md` 에 있습니다.

## 2. 작업 공간이 하나로 합쳐졌습니다

**어제까지 있던 워크트리(`26_AI_platform-design`, 3002)는 없앴습니다.**
디자인 브랜치를 `main` 에 병합했기 때문입니다. 이제 폴더 하나, 포트 하나입니다.

| | |
|---|---|
| 폴더 | `C:\Users\사용자\Documents\26_AI_platform` |
| 브랜치 | `main` |
| 포트 | 3000 |
| 데모 데이터 | `.data` |

> `26_AI_platform-design` 폴더에 `node_modules` 안의 DLL 몇 개가 남아 있습니다.
> 실행 중인 프로세스가 잡고 있어서 안 지워진 것이고, **컴퓨터를 한 번 껐다
> 켜면 폴더째 지울 수 있습니다.** 안 지워도 아무 문제 없습니다.

### ⚠️ 개발 서버(`pnpm dev`) 대신 운영 모드로 띄웁니다

Next 16 + Turbopack 개발 모드가 이 환경에서 불안정합니다. 쓰다 보면 렌더링
워커가 죽고, 그때부터 **주소에 ID 가 들어가는 상세 화면이 전부 500** 을 냅니다
(목록은 멀쩡해서 "수요 상세만 고장"처럼 보입니다). 원인을 좁혀 봤지만 데이터도
계정도 아니었고, 마감 앞두고 파고들 값이 없다고 판단했습니다.

```powershell
cd C:\Users\사용자\Documents\26_AI_platform
pnpm build      # 1~2분
pnpm start      # http://localhost:3000
```

운영 모드는 워커도 핫리로드도 없어서 죽을 구조가 아닙니다. 수요 상세 60회
연속 요청에 실패 0회로 확인했습니다. **대신 코드를 고치면 자동 반영이 안 되니
`pnpm build` 를 다시 돌려야 합니다.**

화면이 이상하면 먼저 `.next` 를 지워 보세요. 어제 상세 화면이 전부 404 였던
것은 이 캐시가 1.8GB 까지 부풀어 깨졌기 때문이었습니다.

```powershell
Get-NetTCPConnection -LocalPort 3000 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
Remove-Item -Recurse -Force .next
pnpm build; pnpm start
```

## 3. 오늘 한 일

### 맞춤 AI 찾기 마법사 (리뷰 2절)

수요 등록의 빈 칸 다섯 개를 **버튼 다섯 단계**로 바꿨습니다. 서술형은 5단계에
한 칸만, 그것도 선택으로 남겼습니다.

- **랜딩 `/`** — 로그인 없이 열립니다. `맞춤 AI 찾기 마법사` / `AI 플랫폼 들어가기` 두 갈래
- **마법사 `/wizard`** — 5단계 → 비슷한 도구 추천 → 없으면 수요 초안 → 확인 후 등록
- **추천은 모델을 쓰지 않습니다.** 글자 겹침 계산이라 즉시 나오고 근거를 댈 수 있습니다
- **초안 다듬기만** 화면에서 모델을 부릅니다. 실패해도 규칙 초안으로 끝까지 갑니다
- 수요 등록 폼에 **참고 자료** 칸 추가 (2.2절: 저장 전에는 첨부 메뉴가 없었다)

### 디자인 (Phase 1·2 병합 + Phase 3 일부)

- `feature/design-phase1` 을 `main` 에 병합 (충돌 없음)
- 마법사를 **카드 한 장**으로 다시 짬 — 머리(단계)·본문·바닥(이전/다음)
- 진행 표시를 막대에서 **번호 동그라미**로. 지나온 단계는 체크, 지금은 테두리
  (색만으로 구분하지 않기 위해서이기도 합니다)
- **CNU Signal Line** (문서 §11) 을 랜딩·마법사에 하나씩

## 7. 조심할 것

- **API 키가 대화 기록에 평문으로 남았습니다.** 작업이 끝나면 포털에서 한 번
  갈아 주세요. 키는 `.env.local`(gitignore)에만 있고 커밋에는 안 들어갔습니다.
- **`seed-analyses.ts` 를 손으로 고치지 마세요.** `pnpm ai:analyze` 가 덮어씁니다.
- **마법사 질문 문구를 바꾸면 그림도 같이 바꿔야 합니다.** 그림 안에
  "STEP N / 5"와 질문이 그려져 있어서, 어긋나면 눈으로 보는 것과 화면
  낭독기가 서로 다른 말을 합니다.
- **`CLAUDE.md` 규칙 하나와 부딪히는 곳이 있습니다.** "화면·서버 액션에서
  분석을 부르지 마세요"인데, 마법사의 문장 다듬기는 화면 흐름 안에서 모델을
  부릅니다. 요청하신 형태라 그대로 두되, 취지는 지켰습니다 — 도구 추천은
  모델을 안 쓰고, 모델이 없거나 실패해도 규칙 초안으로 끝까지 가고,
  누가 쓴 문장인지 화면에 밝힙니다.
- 되돌리기 전에 읽어야 할 결정은 [DECISIONS.md](DECISIONS.md) 와
  루트 `CLAUDE.md` 에 있습니다.

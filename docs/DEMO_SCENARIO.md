# DEMO 시나리오

화면을 직접 눌러 보며 전체 흐름을 확인하는 순서입니다.
E2E 테스트(`e2e/full-workflow.spec.ts`)가 자동으로 하는 것과 같은 흐름입니다.

## 준비

```powershell
pnpm demo:reset
pnpm dev
```

http://localhost:3000

> 화면의 모든 기관·부서·사용자·도구 정보는 **가상의 예시 데이터**입니다.
> 상단에 항상 DEMO 배너가 뜨고, 도구명과 수요 제목에는 `[예시]` 접두어가 붙습니다.
> 이메일은 RFC 2606 예약 도메인 `demo.university.test` 를 씁니다.

## 1. 역할에 따라 화면이 어떻게 다른지 보기

**박수요(수요자)로 로그인**

- 사이드바에 `대시보드 · 자동화 도구 · 업무 수요 · 개선 요청` 만 보입니다.
- `/tools` 목록에 **5건**이 보입니다. 김개발의 임시저장 도구는 빠집니다.
- 주소창에 `/reviews` 를 직접 입력해 보세요 → **404**.
  화면에서 메뉴를 감춘 것은 편의이고, 실제 차단은 서버가 합니다.

**최관리(관리자)로 로그인**

- 사이드바에 `검토 작업 · 관리` 가 추가됩니다.
- `/tools` 목록에 **6건**이 보입니다.

## 2. 도구 등록 (김개발)

`자동화 도구 → 도구 등록`

5단계 위저드입니다. 언제든 임시저장할 수 있습니다.

1. **기본 정보** — 이름, 한 줄 소개, 카테고리, 담당 부서, 설명, 해결하려는 문제
2. **기능과 업무 흐름** — 주요 기능(Enter 로 추가), 현재/자동화 후 흐름, 입력·출력
3. **연동과 데이터** — 연동 시스템, **다루는 데이터 종류**, 저장 위치, 보관 기간
   - 개인정보·성적·상담 같은 민감 분류를 고르면 그 자리에서 경고가 뜹니다.
   - "외부 서비스로 전송" 을 켜면 전송 대상 입력이 필수로 바뀝니다.
4. **비용과 성과** — 전부 선택 항목. **모르는 항목은 비워 두세요.**
   0원과 "파악하지 못함"은 다르게 기록됩니다.
5. **첨부와 확인** — 저장 전에는 첨부를 올릴 수 없다고 안내합니다.
   `임시저장` 을 누르면 첨부 영역이 열립니다.

빈 칸을 남긴 채 `다음` 을 눌러 보세요. 문제가 있는 칸이 빨간 테두리와 함께
"무엇이 잘못됐고 어떻게 고치면 되는지"를 알려 줍니다.

`등록 신청` → 도구 상세로 이동합니다.

## 3. 검토와 보완 요청 (이검토)

`검토 작업` → 방금 등록한 도구

- 큐는 **내가 맡은 건 → 배정 대기 → 나머지** 순입니다.
- 민감정보를 다루는 도구와 체크리스트 미작성 건에 배지가 붙습니다.

`이 도구 검토 맡기` 를 누르면 상태가 자동으로 `담당자 검토` 로 넘어갑니다.

**여기서 `시범운영 승인` 버튼이 없는 것을 확인하세요.**
위험 체크리스트가 없으면 서버가 전환을 막기 때문에 버튼 자체가 나오지 않습니다.

`보완 요청` → 이유(5자 이상)와 검토 의견 입력 → 저장

## 4. 수정과 재신청 (김개발)

도구 상세 → `수정`

"보완 요청을 받은 도구입니다" 안내가 뜹니다.
3단계에서 보관 기간을 고치고, 5단계에서 변경 사항을 적은 뒤 `보완 후 재신청`.

## 5. 체크리스트와 승인 (이검토)

`검토 작업` → 도구 → `검토 시작` (재신청되어 `등록 신청` 상태로 돌아와 있습니다)

**위험 체크리스트 14항목**을 확인합니다.

- 항목을 체크하면 통제 방안 입력칸이 나타납니다. **비워 두면 저장되지 않습니다.**
- 아래에 "참고용 제안 등급"이 보이는데, 화면에 적힌 대로 **AI 분석이 아니라
  체크된 항목 수를 세는 단순 규칙**입니다.
- `매우 높음` 을 골라 보세요 → "시범운영과 정식 승인으로 넘어갈 수 없습니다"
  경고가 뜹니다. 저장 후 시범운영 승인 버튼이 사라지는 것도 확인해 보세요.

`낮음` 으로 되돌린 뒤 근거를 적고 저장 → `시범운영 승인` 버튼이 나타납니다.

## 6. 평가 (박수요)

도구 상세 상단 → `평가하기`

7개 항목을 1~5점으로 고릅니다. 점수는 **숫자 + 텍스트 라벨**로 표시됩니다.
하나라도 빠지면 저장 버튼에 "N개 항목 남음" 이 뜹니다.

저장 후 `평가` 탭에서 항목별 평균을 볼 수 있습니다.
`평가하기` 버튼이 `내 평가 수정` 으로 바뀝니다 — **중복 평가는 막힙니다.**
수정하면 이전 값이 이력에 남고 "N회 수정됨" 이 표시됩니다.

## 7. 개선 요청 (박수요)

도구 상세 상단 → `개선 요청`

제목, 유형, 상세 내용, 업무 영향도, 시급도를 입력하면 개선 요청 상세로 이동합니다.

`개선 요청` 메뉴에서 전체 목록을 볼 수 있습니다.
`내 담당` · `내가 요청` 필터가 있습니다.

## 8. 수요와 수동 매칭

**박수요로 `업무 수요 → 수요 등록`**

제목만 있으면 임시저장됩니다. 공개하려면 현재 업무 처리 방식, 가장 번거로운 단계,
원하는 결과물, 꼭 필요한 기능이 필요합니다.

**이검토(검토자)로 수요 상세**

`도구 연결` 버튼이 보입니다. 박수요에게는 보이지 않습니다.

도구를 고르고 → 연결 유형 5종 중 선택 → **연결 사유를 10자 이상** 적습니다.
자동 추천이 아니라 사람이 판단해 연결하는 것이라 근거를 남깁니다.

**김개발(개발자)로 같은 수요**

`개발 참여 신청` 버튼이 보입니다. 검토자·수요자에게는 보이지 않습니다.

## 9. 관리자 화면 (최관리)

`관리`

- **현황** — 지표 8종 + 상태별·카테고리별·부서별 분포. 차트 라이브러리 없이
  CSS 막대 + 숫자 라벨 + 표 마크업이라 스크린리더도 읽을 수 있습니다.
- **사용자** — 역할 변경(사유 필수), 소속·직위 수정, 계정 활성/비활성
  - 자기 자신의 역할 변경 버튼은 **비활성화**되어 있습니다.
- **부서** — 소속 인원이나 도구가 있으면 삭제 버튼이 잠깁니다.
- **카테고리** — 사용 안 함으로 바꾸면 도구 등록 화면 선택지에서 빠집니다.
- **감사 로그** — 지금까지 한 작업이 전부 남아 있습니다.
  **바뀐 값이 아니라 필드 이름만** 기록된 것을 확인하세요.

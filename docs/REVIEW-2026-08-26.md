>
> 이 파일을 채워 주시면 그 내용을 그대로 수정 작업 목록으로 씁니다.
> 다 채우지 않아도 됩니다. **비어 있는 칸은 "문제 없음"으로 읽습니다.**

지난 리뷰는 화면을 하나씩 훑는 방식이었습니다. 이번에는 **실제로 만드신 자동화
도구를 올려서 수요 등록부터 평가까지 한 바퀴 돌려 보는** 방식입니다.
그래서 양식도 화면 순서가 아니라 **일하는 순서**로 짜여 있습니다.

## 0. 시작하기 전에

### 서버 띄우기

```powershell
pnpm demo:reset     # 데모 데이터 초기화 (리뷰 중 뭘 눌러도 되돌릴 수 있습니다)
pnpm dev            # http://localhost:3000
```

### 데모 계정

비밀번호가 없습니다. 로그인 화면에서 카드를 누르면 바로 들어갑니다.

권한이 **역할 하나가 아니라 축 셋**으로 나뉩니다. 계정 종류(이용자/관리자),
관리자가 받은 세부 권한, 그리고 학내 신분입니다. 신분은 권한이 아니라 추천
대상 표시에만 씁니다.


| 이름  | 계정  | 관리 권한  | 신분  | 이 계정으로 볼 것              |
| --- | --- | ------ | --- | ----------------------- |
| 김개발 | 이용자 | 없음     | 교직원 | 도구 등록·수정, 개선 요청 처리      |
| 박수요 | 이용자 | 없음     | 교직원 | 수요 등록, 평가, 개선 요청        |
| 정연구 | 이용자 | 없음     | 교원  | 남의 임시저장 도구가 안 보이는지      |
| 한상담 | 이용자 | 없음     | 학생  | 학생에게 무엇이 보이는지           |
| 이검토 | 관리자 | 검토만    | 교직원 | 검토 큐·체크리스트. 계정 관리는 막힘   |
| 최관리 | 관리자 | 전체(6종) | 교직원 | 관리 메뉴 전체, 감사 로그, 통합 표준화 |


### ⚠️ 도구를 새로 올리면 AI 분석이 비어 있습니다

분석은 **미리 돌려 두고 화면은 저장된 것만 읽습니다.** 그래서 리뷰 중에 새 도구를
등록하시면 그 도구에는 분석이 없고, 화면에 "아직 돌리지 않았습니다"가 뜹니다.
**고장이 아닙니다.** 아래를 실행하면 채워집니다.

```powershell
pnpm ai:analyze -- --only=duplicates   # 중복 탐지만 (빠름)
pnpm ai:analyze                        # 전부 (32회, 약 $1.2)
pnpm demo:reset                        # 결과를 데모 데이터에 반영
```

> **이것 자체가 리뷰 대상입니다.** 실제 운영이라면 등록 신청을 누르는 순간
> 자동으로 돌아야 맞습니다. 지금은 시연 안정성을 위해 수동으로 두었습니다.
> 8.3 항목에서 어느 쪽이 좋을지 정해 주세요.

### 채우는 법

- 판정 칸의 `⬜` 중 해당하는 것을 `✅` 로 바꿔 주세요.
- **판단이 어려우면 `애매` 에 표시하고 메모에 왜 걸리는지만 적어 주세요.**
제가 선택지를 정리해 다시 여쭙겠습니다.

- 화면을 캡처하셨다면 `docs/review-shots/` 에 넣고 파일명을 메모에 적어 주세요.

### 2.3 수요 상세 — 이미 있는 도구로 되는지

수요를 올리면 상세 화면에 **"이미 있는 도구로 되는지 확인"** 카드가 뜹니다.
(새로 올린 수요라면 `pnpm ai:analyze -- --only=demands` 를 돌려야 나옵니다.)


| 항목                                       | 판정                | 메모  |
| ---------------------------------------- | ----------------- | --- |
| 판정 세 갈래(그대로 됨/조금 고치면 됨/새로 만들어야 함)가 이해되는가 | ⬜ 좋음 ⬜ 애매 `✅` 고쳐야 |     |
| **"이 도구로는 안 되는 것"** 목록이 쓸모 있는가           | ⬜ 좋음 ⬜ 애매 `✅` 고쳐야 |     |
| 설명 문장이 읽을 만한가                            | ⬜ 좋음 ⬜ 애매 `✅` 고쳐야 |     |
| 판단이 실제로 맞는가                              | ⬜ 맞음 ⬜ 애매 `✅` 틀림  |     |
| 어느 모델이 언제 판단했는지 표시                       | ⬜ 좋음 ⬜ 애매 `✅` 고쳐야 |     |


**2절에서 고쳐 주세요 (수요올리기 파트가 가장 중요하고 가장 우선 작업)**

- [수요 등록]은 아예 형태를 변경해야함. '맞춤 AI 찾기 마법사'로 버튼을 눌러가며 내용을 작성하고, 이 기능을 통해 [수요 등록]도 할 수 있는 형태로 가자. 서술형은 최소화 하되, 선택사항으로 맨 마지막에 입력 할 수 있는 형태로 수정하자. 랜딩페이지를 별도로 가져가고 첫 화면에서부터 'AI 플랫폼 들어가기'와 '맞춤 AI 찾기 마법사'를 선택해서 안내를 해주는 형태가 좋겠어. 여기에 들어가는 이미지도 별도로 만들테니, 버튼과 UX 형태를 먼저 구현해줘. 들어가야할 이미 사이즈는 표기해줘. 'AI 플랫폼 들어가기'을 누르면 기본 홈 화면으로 이동하고, '맞춤 AI 찾기 마법사'를 누르면 이용자가 직접 해결하고자 하는 문제를  단계별로 버튼을 눌러가며 찾고싶거나 수요하는 AI 도구를 정의하는 기능이야.
- '맞춤 AI 찾기 마법사'에서 각 단계마다 들어가는 이미지 에셋은 별도로 만들어서 줄테니까 일단은 비워놔줘. 필요한 면적에 따라 이미지를 수정해서 줄꺼야. 먼저 UX 형태를 먼저 만들어주고 들어가야 할 이미지 사이즈를 표기해줘. 구현하고자 하는 UX 구조는 다음과 같아.  **STEP 1 / 5** 무슨 일을 하고 싶나요?

  **STEP 2 / 5** 어떤 자료를 사용하나요?

  **STEP 3 / 5** 어떤 결과가 필요하나요?

  **STEP 4 / 5** 얼마나 자주 하나요?

  **STEP 5 / 5** 중요한 조건이 있나요? 이 질문이 끝나면 마지막에 기존에 있는 도구중에 추천을 해주거나, 적당한 도구가 없다면 수요 요청을 하는 단계로 이어지도록 설계하자. 멀티 LLM을 통해 작성해야하는 내용을 자동으로 작성하고 마지막에 확인하고 수요 등록하는 형태로 구현

**우선순위**: `✅` 높음 ⬜ 보통 ⬜ 낮음

### 3.3 신청 직전 안내

마지막 단계에 **"신청하면 등록 내용이 자동 확인됩니다"** 안내가 있습니다.


| 항목                           | 판정                | 메모  |
| ---------------------------- | ----------------- | --- |
| 무엇이 외부로 나가고 무엇이 안 나가는지 이해되는가 | `✅` 좋음 ⬜ 애매 ⬜ 고쳐야 |     |
| 이 안내가 있어서 안심이 되는가, 오히려 불안한가  | `✅` 안심 ⬜ 애매 ⬜ 불안  |     |


**3절에서 고쳐 주세요**

- 가장 치명적인 것은 자동화 도구를 올릴 수가 없음. 파일이든, URL이든 연결시켜야하는데 그것을 넣을 수 있는 칸이 없음.
- 그리고 자동화 도구를 올렸으면 수정을 할 수가 없음. 개발자가 자신이 올린 글을 수정할 수 있는 권한과 기능이 있어야 함.
- 올라간 자동화 도구를 다운 받거나 실행할 수 있는 버튼이 없음.

**우선순위**: `✅` 높음 ⬜ 보통 ⬜ 낮음

## 4. AI 분석 — 이 플랫폼의 핵심

> 여기서 `pnpm ai:analyze` 를 돌린 뒤 `pnpm demo:reset` 하고 다시 보세요.

**이검토**로 로그인해서 검토 작업 → 방금 올린 도구로 들어갑니다.

### 4.1 중복 자동화 탐지


| 항목                            | 판정              | 메모  |
| ----------------------------- | --------------- | --- |
| 겹치는 도구를 제대로 찾았는가              | ⬜ 맞음 ⬜ 애매 ⬜ 틀림  |     |
| **놓친 것이 있는가** (겹치는데 못 찾음)     | ⬜ 없음 ⬜ 있음       |     |
| **엉뚱한 것을 잡았는가** (안 겹치는데 찾음)   | ⬜ 없음 ⬜ 있음       |     |
| 판정 4단계 이름이 이해되는가              | ⬜ 좋음 ⬜ 애매 ⬜ 고쳐야 |     |
| 처리 제안(합치기/역할 나누기/그대로)이 쓸모 있는가 | ⬜ 좋음 ⬜ 애매 ⬜ 고쳐야 |     |
| 겹치는 점 / 다른 점을 나란히 보여 주는 방식    | ⬜ 좋음 ⬜ 애매 ⬜ 고쳐야 |     |
| "표현이 겹치는 정도"를 따로 적은 것이 헷갈리는가  | ⬜ 괜찮음 ⬜ 헷갈림     |     |


### 4.2 위험도 자동 평가


| 항목                              | 판정                    | 메모  |
| ------------------------------- | --------------------- | --- |
| 제안 등급이 타당한가                     | ⬜ 맞음 ⬜ 애매 ⬜ 틀림        |     |
| 14개 항목 판단에 **근거 인용**이 붙어 있는가    | ⬜ 좋음 ⬜ 애매 ⬜ 고쳐야       |     |
| **체크리스트를 자동으로 안 채우는 것**에 동의하시는가 | ⬜ 동의 ⬜ 애매 ⬜ 채워 주면 좋겠다 |     |
| 제안을 보고 체크리스트를 채우기 편했는가          | ⬜ 좋음 ⬜ 애매 ⬜ 고쳐야       |     |
| 검토자 판단과 갈린 항목을 보여 주는 것          | ⬜ 좋음 ⬜ 애매 ⬜ 고쳐야       |     |
| 권장 통제 문구가 실무에 맞는가               | ⬜ 좋음 ⬜ 애매 ⬜ 고쳐야       |     |


### 4.3 멀티 LLM 품질검증


| 항목                           | 판정              | 메모  |
| ---------------------------- | --------------- | --- |
| 두 관점(내용 일관성 / 규정·보안)이 적절한가   | ⬜ 좋음 ⬜ 애매 ⬜ 고쳐야 |     |

| ----------------------------- | --- |

### 8.2 관리자가 디자인을 바꾸는 기능

말씀하신 기능입니다. 범위에 따라 크기가 많이 달라집니다.


| 물음                                                | 답   |
| ------------------------------------------------- | --- |
| 어디까지 바꾸고 싶으신가 — ⬜ 색·로고·학교명 정도 ⬜ 글꼴·간격까지 ⬜ 화면 배치까지 |     |
